Subject: Jeen Insights - architecture and installation guide

Jeen Insights deployment overview

Hello team,

Jeen Insights is a governed natural-language analytics application. Users ask business questions in plain language; the service uses curated Schema Modeler metadata, an approved LLM, and read-only data connections to generate and run SQL/DAX, explain results, create charts, and run optional ML analysis.

Architecture in short

UI image Flask/Gunicorn browser entry point and BFF. It owns login, sessions, CSRF, and signed UI-to-API tokens. This is the only externally exposed service.
API image Internal FastAPI/LangGraph service for catalog lookup, governed query generation, execution, charts, conversations, connectors, and LLM calls.
Analytics image Internal isolated sandbox for validated statistical and ML operations. It uses a separate internal secret and is deployed without external egress.
PostgreSQL Required shared metadata database: Schema Modeler catalog plus Insights-owned users, settings, conversations, saved artifacts, and connector records.
Data and LLM Runtime data connections can include PostgreSQL, Trino/Presto, Databricks, and Power BI. The LLM is selected from the shared model catalog or the documented environment fallback.
Identity Local accounts, direct Microsoft Entra ID, or OIDC through Keycloak/Zitadel. Client secrets remain in the target platform's secret manager.
Blob / S3 Not required. Persistent product data and saved artifacts are stored in PostgreSQL; container images are stored in ACR, ECR, or the OpenShift internal registry.

Installation process

  1. Prepare the registry: push the three immutable images.
  2. Configure values and secrets: database, LLM, public URL, TLS, identity, and internal signing keys.
  3. Preflight: lint/render Helm, verify pulls, DNS, TLS, PostgreSQL, IdP, and network paths.
  4. Migrate: back up PostgreSQL, run the explicit migration Job, wait, and review logs.
  5. Install: deploy the same immutable image set with Helm or allow Argo CD to sync it.
  6. Verify: check all rollouts, health JSON, login, one governed query, and one ML operation when enabled.

Choose the target environment

  • Azure AKS installation - ACR, Workload Identity, Key Vault/External Secrets, ingress or internal LoadBalancer.
  • AWS EKS installation - ECR, IRSA/Pod Identity, Secrets Manager, ALB/NLB, ACM, and Route 53.
  • Air-gapped OpenShift installation - offline bundle, internal registry, restricted SCC, Route, and checksum validation.
  • Argo CD / GitOps installation - reviewed image promotion and separate secret, migration, and workload phases.

Use either direct Helm or Argo CD as the release owner for an environment, never both at the same time.

Before installation, please confirm the target platform, registry, namespace, public URL/TLS, PostgreSQL endpoint and migration role, identity provider, LLM endpoint/model, and required outbound network access.

Security note: do not send credentials by email and do not commit populated values. Store secrets in Azure Key Vault, AWS Secrets Manager, an approved OpenShift/Kubernetes Secret process, or the organization's designated secret manager.
